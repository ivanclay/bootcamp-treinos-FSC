# Template de Prompt para Alterar Rotas de API

Adicione **objetivo** e **imagem de capa** ao plano de treino, permita **mudar o objetivo** pelo chat e **salve o nome** informado no onboarding.

## Descrição

A tela "Plano de Treino" do Figma mostra uma imagem de capa e uma tag com o objetivo do plano (ex: "HIPERTROFIA & FORÇA"). O chat tem o atalho "Mudar objetivo". No onboarding, o Coach AI pergunta o nome da pessoa, mas hoje o nome não é salvo.

## Requisitos Técnicos

- Crie o enum `WorkoutGoal` no `prisma/schema.prisma`: `HYPERTROPHY`, `STRENGTH`, `HYPERTROPHY_AND_STRENGTH`, `WEIGHT_LOSS`, `CONDITIONING`, `HEALTH`.
- Adicione ao model `WorkoutPlan` os campos opcionais `goal WorkoutGoal?` e `coverImageUrl String?`.
- Gere a migration com `pnpm exec prisma migrate dev --name add-workout-plan-goal-and-cover`.
- **SEMPRE** use `z.enum(WorkoutGoal)` importado de `../generated/prisma/enums.js` nos schemas. **NUNCA** use `z.string()` para o objetivo.
- Altere os use cases `CreateWorkoutPlan`, `GetWorkoutPlan` e `ListWorkoutPlans` para receber/retornar `goal` e `coverImageUrl`.
- Altere o use case `UpsertUserTrainData` para receber `name` opcional.
- Altere a tool `createWorkoutPlan` (@src/routes/ai.ts) para receber `goal` (obrigatório) e `coverImageUrl` (opcional).
- Altere a tool `updateUserTrainData` (@src/routes/ai.ts) para receber `name` (opcional).

## Autenticação

- Rotas protegidas (sem mudança).

## Request

`POST /workout-plans`

```ts
interface Body {
  name: string;
  goal?: WorkoutGoal;
  coverImageUrl?: string; // URL
  workoutDays: Array<{
    /* sem mudança */
  }>;
}
```

`PUT /me`

```ts
interface Body {
  name?: string; // trim, mínimo 1 caractere
  weightInGrams: number;
  heightInCentimeters: number;
  age: number;
  bodyFatPercentage: number;
}
```

## Response

`GET /workout-plans/:id`, `GET /workout-plans` e `POST /workout-plans` passam a incluir:

```ts
interface WorkoutPlanFields {
  goal?: WorkoutGoal;
  coverImageUrl?: string;
}
```

`PUT /me` passa a incluir:

```ts
interface StatusCode200 {
  userName: string;
  // ...campos atuais
}
```

## Regras de Negócio

- Se `coverImageUrl` do plano não for informado, o use case usa a capa do primeiro dia de treino (não descanso) que tiver capa. Se nenhum tiver, fica vazio.
- Planos antigos continuam válidos: `goal` e `coverImageUrl` vazios não são erro.
- `name` só é alterado quando informado; string vazia não é aceita.
- **Mudar objetivo** (Coach AI): a IA consulta o plano ativo (`getWorkoutPlans`), pergunta o novo objetivo e confirma se os dias e restrições continuam os mesmos. Depois cria um novo plano com `createWorkoutPlan` (o plano anterior é desativado pelo use case).
- **Onboarding** (Coach AI): ao salvar os dados com `updateUserTrainData`, a IA envia também o `name` informado.
