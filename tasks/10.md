# Template de Prompt para Corrigir Bugs

Corrija os bugs encontrados na revisão do código (comparação com o Figma).

## Descrição

Três problemas: um de isolamento entre usuários, um de cálculo da sequência (🔥) e um de configuração do ambiente.

## Bug 1 — Criar um plano desativa o plano de outra pessoa

Em @src/usecases/CreateWorkoutPlan.ts, o plano ativo é buscado com `where: { isActive: true }`, **sem `userId`**. Criar um plano desativa o plano ativo de qualquer usuário.

- A busca e a desativação devem filtrar pelo `userId` do DTO.
- A busca deve ficar **dentro** da transação.
- Todos os planos ativos do usuário devem ser desativados (`updateMany`), não só o primeiro.

## Bug 2 — Sequência cai para 0 enquanto o treino de hoje não é concluído

Em @src/usecases/GetHomeData.ts e @src/usecases/GetStats.ts, o cálculo da sequência começa na data de referência e para no primeiro dia de treino sem sessão concluída. Como o treino de hoje ainda não foi feito de manhã, a Home mostra 🔥 0 até a pessoa concluir o treino.

Além disso, os dois use cases têm cópias diferentes do mesmo cálculo: em `GetStats` os dias de descanso não contam, contrariando a @tasks/06.md.

### Requisitos Técnicos

- Extraia o cálculo para uma função pura `calculateWorkoutStreak` em `src/lib/workout-streak.ts` (sem acesso ao banco). Os use cases continuam buscando as sessões com o Prisma e passam os dados para a função.
- Recebe um objeto: `{ workoutDays, completedDates, referenceDate, planCreatedAt }`.

### Regras de Negócio

- A data de referência (hoje) **não quebra** a sequência: se estiver concluída, conta; se não, é ignorada.
- Dia de treino concluído: conta +1.
- Dia de descanso: conta +1, mesmo sem sessão.
- Dia da semana que não está no plano: pula, sem contar.
- Dia de treino anterior à referência sem sessão concluída: para.
- Dias anteriores à criação do plano (`planCreatedAt`) não contam: a contagem para ali.
- Em `GetStats`, a data de referência é o menor valor entre `to` e hoje (UTC), para que um `to` no futuro não zere a sequência.

## Bug 3 — Chave errada obrigatória no ambiente

Em @src/lib/env.ts, `GOOGLE_GENERATIVE_AI_API_KEY` é obrigatória, mas o chat usa a OpenAI (`OPENAI_API_KEY`, hoje opcional). Sem a chave da OpenAI o servidor sobe e o chat falha.

- `OPENAI_API_KEY` passa a ser obrigatória.
- `GOOGLE_GENERATIVE_AI_API_KEY` passa a ser opcional.
- Atualize `.env.example` e o README.
